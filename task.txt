Роль: Ты Senior Frontend Developer с опытом создания сложных клиентских шахматных веб-приложений.
Задача: Написать полностью клиентское веб-приложение (SPA) — интерактивный шахматный тренажер для учеников с продвинутой логикой поиска угроз.

Стек технологий:

Сборщик: Vite

Стилизация: Tailwind CSS v4 (для основного интерфейса) + Vanilla CSS (для точечной кастомизации chessground).

UI доски: chessground (как на Lichess)

Шахматная логика: chess.js

Движок: stockfish.js (WebWorker/WebAssembly)

Отправка отчетов: API Formspree или EmailJS (полностью на клиенте)

1. Глобальные настройки (UI стартового экрана)
Перед началом новой партии пользователь видит экран настроек. Все настройки должны автоматически сохраняться в localStorage и подтягиваться при следующем визите.

Имя ученика: Текстовое поле.

Сила Stockfish: Выбор Elo (например, от 1000 до 2500) или уровня Skill Level.

Таймер на поиск угроз: Время (в секундах) на каждый ход, выделенное на этап поиска шахов и взятий.

Подсказки (Show target counts): Чекбокс, включающий отображение количества целей для поиска в текущей позиции.

Общий таймер игры: Классический контроль времени (например, 10 минут + 5 секунд на ход).

2. Сохранение состояния (Persistence)
Приложение должно быть устойчивым к перезагрузке страницы.

Каждое изменение состояния (сделан ход, найден один из шахов, изменилось время на таймерах) должно синхронизироваться в localStorage.

Сохраняемые данные: Текущий FEN, PGN, чья сейчас фаза (поиск или игра), оставшееся время на обоих таймерах, накопленная статистика.

При загрузке страницы приложение должно проверять наличие незаконченной партии в localStorage и предлагать «Продолжить партию» или «Начать новую» (со сбросом стейта).

3. Игровой цикл (Core Loop)
Ход ученика (белые) строго делится на две фазы:

Фаза А: Поиск угроз (Доска заблокирована для ходов)

Как только Stockfish делает свой ход (или начинается партия), chessground блокируется для перемещения фигур (viewOnly: true).

Запускается Таймер поиска угроз (паузится Общий таймер).

С помощью chess.js система генерирует списки легальных шахов и взятий, строго разделенные на 4 категории:

Мои шахи (за себя)

Мои взятия (за себя)

Шахи соперника (угрозы королю ученика)

Взятия соперника (какие фигуры ученика под боем)

Если в настройках включены подсказки, UI выводит 4 счетчика:

«Мои взятия: 0/2», «Мои шахи: 0/1»

«Взятия соперника: 0/3», «Шахи соперника: 0/0»

Ученик кликает по фигурам/полям, чтобы указать эти угрозы. Правильные клики подсвечиваются зеленым (через chessground shapes/CSS), ошибки — красным.

Фаза А заканчивается, и доска разблокируется для хода, если выполнено ОДНО из условий:

Ученик нашел 100% целей по всем 4 категориям.

Истек Таймер поиска угроз (ученик не успел).

Фаза Б: Совершение хода

Запускается Общий таймер игры ученика (Таймер поиска сбрасывается).

Ученик делает классический шахматный ход на доске.

Перед передачей хода движку, позиция быстро оценивается Stockfish (сравнивается с первой линией компьютера), чтобы в конце партии посчитать метрику «Процент сильнейших ходов».

Ход передается Stockfish, он делает ответный ход, цикл возвращается к Фазе А.

4. Статистика и завершение партии
Когда партия заканчивается (мат, пат или закончилось время на общем таймере), всплывает модальное окно (Tailwind Modal) с итоговой статистикой.
Собираемые метрики:

Поиск за себя: Шахи X/Y (Z%), Взятия X/Y (Z%).

Поиск за соперника: Шахи X/Y (Z%), Взятия X/Y (Z%).

Точность игры: X% ходов совпали с первой линией компьютера.

Время: Суммарное время, потраченное на поиск угроз (Фаза А), и среднее время на поиск угроз за один ход.

Удаление данных текущей игры из localStorage (оставляем только настройки).

5. Бесшовная отправка отчета
В модальном окне статистики находится кнопка «Отправить тренеру».

Кнопка вызывает POST-запрос (через Formspree/EmailJS) с JSON-объектом.

В письме должен приходить красиво отформатированный текстовый отчет: Имя ученика, дата, и полная выгрузка метрик из пункта 4.

Отправка происходит без перезагрузки (показать Tailwind Toast-уведомление "Отчет успешно отправлен!").

Требования к архитектуре:
Код должен быть модульным. Используй современные возможности Vite. Логика валидации шахов/взятий за обе стороны должна быть выделена в отдельный класс/хук/модуль состояния, не смешиваясь с визуальной логикой chessground. Стилизация UI (кнопки, таймеры, сайдбар с прогрессом поиска) должна быть выполнена на утилитарных классах Tailwind v4. Напиши архитектурный план и базовую реализацию Игрового цикла (Core Loop).
